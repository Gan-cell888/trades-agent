TradeS Agent
外贸客户资料清洗整理 · 产品完整说明

服务对象是外贸软件公司的 ToB 销售人员。 产品把「多渠道客户资料 → 标准化清洗 → 外呼 CRM 拨打 → 腾讯会远程演示 → 跟进签单」 这条每日重复的工作链路自动化、智能化，目标是提高有效接通、演示预约与成交转化。

产品代号TradeS Agent
一句话定位线索工厂 + 演示参谋
交付形态Web 工作台 + CRM 协同
优先级P0 · 先于 Agent B

01 · PRODUCT DEFINITION

产品定义

产品名称

TradeS Agent · 贸清 Agent
外贸客户资料清洗整理 Agent

产品口号

让销售把时间花在签单上，
而不是整理表格和搜资料。

核心价值

清洗提速 70%+
演示准备从 30 分钟 → 3 分钟

要解决的问题

P1

原始数据杂乱

中国制造、阿里巴巴、企查查等多渠道资料格式不一，空号、重复、字段缺失严重，人工清洗耗时且易漏。

P2

模板填报重

公司表格模板字段多，销售每天重复复制粘贴，导入外呼 CRM 前还要再校验一遍。

P3

演示准备慢

官网、B2B 店铺、海外社媒信息分散，销售靠记忆和碎片搜索，演示缺乏针对性。

P4

行业差异大

不同行业/产品线的痛点和开发方式不同，新手销售难快速找到演示侧重点。

P5

跟进易断档

通话、演示、异议、承诺事项散落在聊天和记事本里，丢单原因无法复盘。

P6

经验难复制

Top Sales 的话术与案例沉淀不下来，团队培训成本高。

产品做什么

  • 多源线索导入、清洗、模板导出、写入外呼 CRM
  • 演示前自动企调，输出演示简报与侧重点建议
  • 线索评分、通话/演示/跟进任务管理
  • 话术与案例辅助，结果回收看板

产品不做什么（MVP 边界）

  • 不做外呼拨号器本身（交给外呼 CRM）
  • 不做合同/回款财务系统
  • 不做全自动社交账号群发
  • 不替代公司 BI，只做销售作业闭环

02 · USERS & ROLES

用户与角色

主要用户

ToB 外贸软件销售

目标：完成月度签单指标，提高有效通话与演示转化。

  • 工作内容：清洗线索、外呼、约演示、线上演示、报价跟单
  • 高频动作：每天处理 50–300 条线索；每周 5–20 场演示
  • 核心诉求：少做表格，多打电话；演示更有针对性
  • 熟练度：会用 Excel / CRM，不愿学复杂系统
次要用户

销售主管 / 经理

  • 配置公司清洗模板与权限
  • 查看团队线索消化、演示、签单漏斗
  • 抽查企调报告质量
协同用户

售前 / 产品 / 市场

  • 提供行业案例、功能卖点、竞品对比资料
  • 沉淀知识库，供 Agent 引用

03 · BUSINESS SCENARIOS

业务场景全景

围绕两大主场景展开：数据清洗落库、演示辅助分析；并用跟进管理把线索推到签单。

场景一 · 原始数据清洗

  1. 公司下发渠道资料（中国制造 / 阿里巴巴 / 企查查 / 其他）
  2. 销售上传 Excel/CSV 或粘贴数据
  3. 系统识别字段、去重、校验、补全标签
  4. 按公司模板生成标准表
  5. 导出或直写外呼 CRM，开始拨打

场景二 · 演示辅助分析

  1. 从线索列表选择「准备演示」
  2. 系统调研官网、B2B 平台、海外社媒
  3. 输出行业/产品画像与外贸开发方式判断
  4. 生成演示侧重点、脚本、案例与异议应对
  5. 演示后回收纪要与跟单任务

场景三 · 跟进签单（支撑）

  1. 通话/演示结果一键记录
  2. 异议、预算、竞品、决策人结构化入库
  3. 按阶段生成下一步动作与提醒
  4. 主管看板监控漏斗与丢单原因

04 · FEATURE MODULE 1

功能一 · 原始数据清洗

把多渠道、半结构化的企业客户资料，变成可直接导入外呼 CRM 的公司标准表。

输入 → 处理 → 输出

支持批量文件、粘贴文本、历史批次复用。清洗过程可解释、可人工修正、可一键重跑。

INPUT Excel / CSV / 粘贴文本 中国制造、阿里巴巴、企查查、自采名单
→
PROCESS 识别 · 去重 · 校验 · 补全 规则引擎 + LLM 语义理解
→
OUTPUT 公司模板表 + CRM 导入包 失败行报告 · 清洗日志

4.1 数据源与导入

来源渠道 典型字段 导入方式 清洗重点
中国制造网 公司名、联系人、电话、主营、网址 导出表上传 联系人职位识别、座机/手机分流
阿里巴巴 / 国际站 店铺名、主营产品、国家、联系方式 导出表 / 粘贴 店铺与公司名对齐、重复店铺去重
企查查 / 工商数据 公司全称、法人、成立日期、地址、官网 导出表上传 统一社会信用代码、经营状态过滤
展会 / 自采 / 其他 名片信息、表格、手工录入 Excel / 粘贴 格式修复、缺失补全

4.2 清洗流水线（规则 + AI）

1

结构识别

自动识别表头与列语义（公司名/联系人/电话/网址/地区/行业等），支持人工确认映射。

2

标准化

去空格/全半角/常见错别字；电话去分隔符、+86 归一；网址补协议、去跟踪参数。

3

去重合并

按手机号 / 公司名+地区 / 域名三级去重；重复记录合并保留最完整字段，保留来源追溯。

4

有效性校验

号码格式与号段校验、疑似空号/停机标记、邮箱格式、经营状态、黑名单过滤。

5

智能补全

LLM 补全行业、主营产品、企业规模、外贸属性（是否出口、是否做平台）、决策人猜测。

6

评分排序

按 ICP 匹配度输出优先级分，生成「今日建议拨打」队列。

7

模板导出

映射到公司模板列，生成 Excel/CSV；可 API/文件写入外呼 CRM。

4.3 公司模板字段（可配置）

字段组 字段 必填 规则说明
企业信息 公司名称是去后缀噪音，保留完整工商/常用名
统一社会信用代码否企查查来源优先
所属地区（省/市）是行政区划标准化
官网否自动补 https、去 www 差异用于去重
联系人 姓名是去「经理/总」等职位混入
职位否归一到标准职位词典
手机 / 座机手机是校验号段；座机单独列
业务标签 行业 / 主营产品是标准行业词 + 自由文本
外贸属性否是否出口/平台卖家/工厂/贸易公司
线索来源渠道是枚举：制造/阿里/企查/其他
作业字段 优先级分是系统计算 0–100
负责人 / 批次号是分配与回溯
备注否清洗提示 / 人工补充

4.4 清洗规则明细

去重

精确：手机号、官网域名、信用代码。
模糊：公司名相似度 ≥ 0.92 且同省市 → 进入「疑似重复」人工确认队列。

手机号

去除空格/短横；11 位大陆号；识别 +852/+1 等海外号并标记；重复号合并到同一联系人池。

空值策略

必填缺失 → 标记待补全，不丢弃；补全失败仍可导出，但优先级分降低并打「字段不全」标签。

异常行

纯备注行、合计行、非企业条目（如「样例」）过滤；表头重复行合并；错位数据进人工修正队列。

黑名单

支持导入公司/号码黑名单；已离职、投诉、明确拒绝客户不再进入当日拨打队列。

可追溯

每条记录保留：原始值、清洗后值、规则命中列表、操作人、时间、来源文件。

4.5 输出与 CRM 写入

标准表导出

一键下载公司模板 Excel/CSV；支持「仅导出可拨打」「全部」「异常待修」三种范围。

外呼 CRM 导入

文件直传或 API 写入；字段映射可保存为方案；失败行回传错误原因（如号码格式）。

批次报告

本次清洗：总条数、通过、去重、无效、待补全、耗时、操作人；可导出给主管。

05 · FEATURE MODULE 2

功能二 · 演示辅助分析

演示前自动完成客户背景调查，输出「他是谁、缺什么、我讲什么、怎么讲」。

演示简报 · 标准输出结构

每次生成约 1–2 页，3 分钟能读完，可复制进腾讯会聊天或打印。

1. 客户快照

  • 公司基本信息（名称、地区、类型、规模猜测）
  • 主营产品与目标市场
  • 外贸现状：平台、网站、社媒、疑似团队规模

2. 信息证据

  • 官网关键页面摘要
  • 中国制造 / 阿里国际站店铺摘要
  • LinkedIn / Facebook / YouTube / Instagram 是否存在及活跃度

3. 痛点假设

  • 按行业推断的 3 个高概率痛点
  • 与我方可售功能模块的映射

4. 开发方式判断

  • 更适合：平台运营 / 独立站 / 社媒 / 展会 / 主动开发
  • 演示中应强调对应产品能力

5. 演示脚本建议

  • 开场 2 分钟：行业共性挑战 + 同行案例
  • 核心 20 分钟：3 个优先模块演示顺序
  • 收尾 5 分钟：报价试探 + 约下一步

6. 风险与异议

  • 常见异议 3–5 条 + 应对话术
  • 可能竞品与差异化点
  • 决策链猜测（老板/外贸经理/业务员）

5.1 调研数据源

官网

首页、关于我们、产品页、联系方式；判断是否真做外贸、产品线、品牌调性。

中国制造网

店铺年限、主营、是否付费会员、产品数量；判断平台投入程度。

阿里巴巴 / 国际站

店铺信息、产品、年限、认证；与官网信息交叉验证。

企查查 / 工商

成立时间、人员规模、经营范围、经营状态、知识产权。

海外社媒

LinkedIn 公司页、Facebook、YouTube、Instagram：有无、粉丝、更新频率、内容类型。

销售历史（内部）

过往通话/演示记录、竞品提及、报价、丢单原因；避免重复问已知信息。

5.2 分析维度与生成逻辑

行业识别 产品词 → 标准行业分类 → 行业模板
外贸成熟度 官网 + 平台 + 社媒 + 出口痕迹 → 低/中/高
开发方式匹配 成熟度 × 行业 × 预算信号 → 策略建议
演示路径 策略 → 映射产品模块 → 排序 → 脚本
外贸成熟度 典型信号 演示侧重点
起步期 无独立站/弱官网，未入驻或刚入驻平台 讲清楚数字化外贸路径、基础获客、线索管理
成长期 有平台店铺或独立站，询盘不稳定 询盘转化、客户跟进、多渠道协同、数据分析
成熟期 多平台 + 独立站 + 社媒，团队多人 团队协作、流程自动化、管理报表、与现有系统集成

5.3 演示辅助能力明细

一键企调

输入公司名/官网/线索，3 分钟内出简报；支持重新抓取与人工补充。

证据可回溯

简报结论附来源链接与摘录，销售可自行核对，避免 AI 幻觉误导。

演示脚本

按时间轴输出讲稿要点、可截图的功能点、要提问的需求探询问题。

异议应对库

价格、已有系统、没时间、效果疑虑等标准异议 + 行业化变体。

案例推荐

从知识库匹配同行业/同规模客户案例，生成 30 秒案例话术。

会后摘要

粘贴会议纪要 → 抽取需求、承诺、下一步、负责人、截止日。

09 · BUSINESS RULES

关键业务规则

优先级分模型

行业匹配 30 + 外贸成熟度 25 + 信息完整度 15 + 可达性（手机有效）20 + 历史互动 10。分档：A(≥80) / B(60–79) / C(<60)。

当日队列

默认按优先级分排序；同分按号码可达性与来源新鲜度；销售可手动置顶。

简报生成约束

必须引用至少 1 条外部证据；无官网/平台信息时输出「信息不足」而不是编造；允许人工锁定结论。

CRM 写入

同一手机号 30 天内不重复创建；写入失败保留本地并支持重试；敏感字段脱敏日志。

权限

销售仅见本人及团队内分配线索；主管可见全团队；模板配置仅管理员。

数据留存

原始上传文件默认保留 180 天；可配置删除；导出文件水印记录操作人。

14 · RISKS

风险与对策

风险影响对策
各渠道导出格式频繁变化 清洗失败率上升 映射方案可配置 + 样本自动推荐映射 + 人工确认
LinkedIn/FB 等抓取不稳或不合规 社媒盘点缺失 支持手动粘贴链接；优先公开信息；合规审查
企调信息不足导致幻觉 销售不信任简报 强制证据引用；低置信度显式提示；人工锁定
外呼 CRM 接口不统一 集成成本高 MVP 先做文件标准表；API 适配层按客户配置
销售抵触新工具 使用率低 首页直接服务「今日拨打/今日演示」；减少跳转
企业客户数据隐私 合规风险 权限隔离、脱敏日志、留存期配置、私有化选项
